# Security and scientific limitations

BLUE is a research subsystem, not a production RNG, key vault or cryptographic validation product. Nothing in it is NIST/FIPS certified. No real security keys are generated from experimental/physical sources. All attack examples create their own synthetic material and operate locally.

Measured claims are limited to the saved configuration and threat model. The package does not break AES, ChaCha20, ECDSA used correctly, or Ed25519. Key weakness, nonce reuse, source anomalies and state exposure are distinct events. Ordinary AEAD rejection of a bit flip does not contradict an accepted **recomputed-tag** GCM forgery under nonce reuse.

The diagnostic battery is only three SP800-22-inspired tests. Nonrejection is not randomness, entropy, secrecy or unpredictability certification. No empirical estimator in BLUE supplies a validated min-entropy lower bound. Public replay seeds, hashes, clocks, salts and file recordings contribute no unknown fresh entropy once known. Statistical “health” cannot reveal who knows a seed.

HMAC-DRBG is reused research code with CAVP examples, not a validated full SP800-90C construction. ChaCha expansion uses the library's 64-bit-counter/64-bit-nonce raw primitive and is a research stream generator, not a NIST DRBG or OS RNG replica. Hash-DRBG/CTR-DRBG are deferred: HMAC already isolates the missing-entropy issue, and another hand-written DRBG would add assurance burden without a new decisive hypothesis. No production AES or ChaCha implementation is written here.

Fault intensities for bias/serial/drift are numerical strengths. For structural faults (seed reuse, reduced support, fixed output, rollback, periodic, starvation, exposure), intensity zero disables the fault and any positive intensity enables the declared support/duration; support bits, period and exposed bits carry the severity. One read attempt is one operation. Starvation advances the fault clock and healthy shadow but returns no output. Recovery resumes the counterfactual healthy shadow: it is a simulation intervention, not an automatic repair guarantee.

Raw source monitoring precedes conditioning. A downstream fixed nonce/reset does not alter raw source observations. An all-zero raw nonce seed hashed to 96 bits may look well mixed but repeats; source bias is not propagated as a biased cipher implementation. A source anomaly that does not yield a collision or recoverable key in this finite test is not reported as a demonstrated cryptographic break.

The bounded partial-exposure model leaks a prefix of a small seed identifier. It is not evidence about the attack complexity of leaking a few bits of actual HMAC-DRBG state. Full-state exposure is a separate explicit clone experiment. Reseeding with withheld model input defeats that clone; it does not prove independence/entropy of an actual source or restore messages already encrypted with compromised keys. Application rekeying and persistence remain separate responsibilities.

Counter nonces must be unique **per key**, across workers and restarts. The SQLite ledger reserves before returning; lost/skipped values are harmless. Every user of a key must share the same trusted ledger. Separate files, restored snapshots and adversarial storage can duplicate allocation. Full crash/power-loss behavior and distributed allocation are untested. The in-process duplicate guard is bounded and fails closed when full; it is not durable. Replays of previously valid ciphertexts are a protocol-level issue, not a forgery test here.

Physical processing is limited to read-only descriptive audits and public capture replay. The raw muon export is unavailable in the repository/workspace inventory, so its historical report numbers are not newly reproduced. Effective ADC resolution, independence, unknown attacker side information, conditional entropy and restart health have not been established.

All inferential rates rely on the declared synthetic sampling model. Exact conditional birthday formulas do not apply to arbitrary correlation. Confidence intervals across descriptive rows are not simultaneous. Early-warning leads selected on both events do not establish a universal forecast, and a policy guard at first attempted misuse is prevention, not prediction. A source could be theoretically insecure from startup without any finite-sample observable anomaly.

Future work: independently reviewed complete source qualification, realistic state-compromise threat models, ChaCha20-Poly1305 nonce-reuse integrity algebra, Hash/CTR-DRBG only for distinct implementation hypotheses, persistent key lifecycle with external rollback protection, pre-registered model-specific predictive calibration, and hardware acquisitions with documented restart/environment controls. These are proposed, not completed results.
