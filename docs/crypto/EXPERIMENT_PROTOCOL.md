# Frozen initial research protocol

Version BLUE-1, 2026-11-02. Freeze this design before the `blue-confirm-v1` evaluation. Development uses `blue-smoke-v1`, excluded from scientific rate estimates. Configuration, code hashes and namespace are written before generating calibration or evaluation data. No outcome-driven stopping or tuning is permitted. Any correction must create a new run directory and disclose the reason.

Primary confirmation: **128 independent replica identifiers**, 199 independent healthy calibration trajectories, 256 operations per trajectory, onset 64, 4096 diagnostic bytes, weak-seed supports 8/12 bits, nonce supports 8/12/16 bits. Sensitivity: namespace `blue-sensitivity-v1`, 64 replicas, 199 calibration paths, 512 operations, onset 128; other settings unchanged. These are CPU-only bounded budgets. At most 2 million weak-key candidate attempts and 4 million trajectory operations are accepted by configuration validation. There is no GPU dependency.

The SHA256 domain-separated replay function takes namespace, replica and role. Calibration uses a distinct `/calibration` namespace. Healthy/faulted source paths and all algorithms share inputs **within a replica** for paired comparisons. The three AEAD algorithms are not independent repetitions of nonce collision behavior. Public deterministic streams emulate the stochastic law; independent-seed simulation is not physical independence or a proof of PRF security.

Health and statistical monitoring

- Source score is the maximum of normalized bit-mean deviation, adjacent-equality deviation and exact adjacent-block repetition, computed causally per 32-byte block. The threshold is the `ceil((199+1)*.95)` order statistic of each healthy calibration path's maximum over **all times and scores**, using strict `>` crossings. This jointly addresses the monitored component/time multiplicity under exchangeability. No distribution-free extrapolation to physical sources is claimed.
- RCT/APT from `rnglab15.assessment.Health` are an additional initial-seed screen with declared binary H=1, alpha=2^-20 and W=512. A 256-bit seed does not fill an APT window; a long initial zero run still triggers RCT. These parameters are research assumptions and are not a certified 90B configuration.
- Output diagnostics use full-precision p-values and Holm across three tests within a stream at .01. Their p-values are asymptotic diagnostics. Across streams we estimate nonrejection frequency, not a giant “all tests pass” certificate. SHA256/HKDF and HMAC/ChaCha cells share replica inputs; all four are reported.
- Explicit seed budget checks consume externally asserted **conditional entropy** evidence, not length, empirical Shannon entropy or successful health tests. `synthetic_model` and `external_assessment` name the caller's basis; neither means the library has verified that evidence.

Uncertainty and scientific decision rules

The experimental unit is the entire replica trajectory. Rates use two-sided exact Clopper–Pearson 95% intervals. Four E3 primary one-sided binomial tests use Holm correction; cross-condition descriptive intervals are marginal and labeled as such. Paired alarm-rate differences use a fixed-seed percentile bootstrap of whole replicas (2000 resamples); intervals at deterministic boundaries can degenerate and do not establish superiority.

All paths have common administrative follow-up. Record every first event or censoring, including no-alarm/no-collision paths. Use Kaplan–Meier survival; report `null` median if not reached. Common-horizon event uncertainty is exact binomial; do not claim an extrapolated tail or conditional event-only median. Alarm-to-compromise intervals report observed pairs and selection explicitly, exclude pre-fault alarms from credited warning times, and are not time-to-insecurity guarantees.

Analytical sensitivity uses P(collision by m)=1-product(i=0..m-1)(1-i/2^b) for IID uniform finite support. For SHA256-truncated toy support this additionally assumes no mapping collisions; those would only worsen uniqueness. This is not a law for Markov, drift or rollback sources. Uniform b-bit seed search has at most 2^b candidates and mean (2^b+1)/2 under uniform candidate order; deterministic conditioning cannot enlarge its support. For a known seed, conditional uncertainty is zero. For real 128/256-bit inputs report these formulas, not practical recovery claims.

Model insecurity, observed misuse and demonstrated compromise can be simultaneous or differently ordered. The same raw source path paired with a reset counter produces an immediate application fault invisible to a source-only test. The same output bytes with different attacker knowledge have identical diagnostics. These identifiable counterexamples limit forecasting; no forecast is fitted or validated in BLUE-1.

Operational overhead: record total campaign runtime, nonce-set entries, extra primitive calls, blocked operations, plus a separate repeated microbenchmark for source scores/guard/SQLite. Wall time is nonreplayable observational metadata; scientific results, configs and hashes are replayable. Performance numbers do not validate a production deployment.

Scientific review must check fixed vectors, misuse/negative controls, fault placement, healthy calibration, censoring, source/consumer pairing, guard call order, replay hashes, and unchanged legacy tests. A successful test suite establishes regression behavior, not the validity of all model assumptions.
